# REPORTE TÉCNICO V2: IMPLEMENTACIÓN DE API SEGURA (POWER BI)
# Fecha: 2026-03-29
# Módulo: advanced_metrics (Zoraen_cookokitchen)
# Estado: API REST Segura Activa (Zero Trust)

INTRODUCCIÓN:
Este documento certifica la ampliación del módulo 'advanced_metrics' para proveer una comunicación autónoma y segura desde Odoo 17 Enterprise hacia Microsoft Power BI o cualquier otra herramienta de Analítica Inteligente (BI). Tras un análisis de riesgos y buenas prácticas éticas, se rechazó la exposición abierta usando credenciales de Odoo y se desarrolló un endpoint basado en Tokens Criptográficos.

==================================================
   RESUMEN DE ARCHIVOS CREADOS / MODIFICADOS
==================================================

1. [NUEVO] models/api_config.py
   - Se creó el modelo persistente 'advanced_metrics.api.config'.
   - Campos Clave:
     - 'access_token': Token UUID v4 irrepetible y no predecible de 128 Bits.
     - 'record_limit': Parametrización en la interfaz para poner topes al tamaño de descargas (por defecto, 5000 registros). Impide ataques que ahoguen o saturen al servidor.
     - 'api_url': Un campo concatenado virtual para que el empleado copie íntegra la ruta de extracción.

2. [MODIFICADO] models/report_wizard.py
   - Se inyectó dinámicamente un nuevo argumento (limit=x) dentro del método 'get_sales_orders_report_rows'.
   - Esto hace que, independiente de lo que un hacker intente pedir, el cálculo en backend siempre trunque el resultado a lo estipulado por seguridad, en vez de un límite rígido como estaba antes.

3. [MODIFICADO] controllers/controllers.py
   - Endpoint Clave: '/api/advanced_metrics/sales_inventory'
   - Se desarrolló un nuevo controlador GET para responder en HTTP con 'auth="public"', esto quiere decir que PowerBI puede llegar sin navegar (navegador simulado). 
   - Lógica de Filtro: Este método LEE la URL evaluando si existe "?token=". Si no está, devuelve 401 "Token Missing". Si la base de datos de Odoo lo rechaza por no cuadrar como token válido, bota 401 "Invalid token".
   - Al pasar este escudo, ejecuta el sudo() para traer los datos bajo lectura rápida de JSON puro en forma de diccionario simple ('data').

4. [NUEVO / MODIFICADO] views/api_config_views.xml & security/ir.model.access.csv
   - Se creó un formulario intuitivo, "Configuración API PowerBI", donde puedes generar más tokens y presionar el Botón Rojo: "Generar Nuevo Token". Éste sobreescribe la secuencia de seguridad y prohíbe instantáneamente usos previos de las URL de BI.
   - Seguridad: El modelo está emparejado para que sus registros sean de Exclusivo acceso al grupo Maestro ('base.group_system'). 
   - Y finalmente se anidó la llamada de estas pantallas bajo el menú de tu Panel Principal ("Advanced Metrics > Credenciales Power BI") de modo que está al alcance desde tu mismo módulo y no en configuraciones ocultas.

==================================================
   VENTAJAS COMPETITIVAS DE LA IMPLANTACIÓN
==================================================
- VELOCIDAD: Estar entregando el formato final del cruce de almacén-inventario (en `qty_to_produce`) en formato nativo JSON hace que los consumos tardos de Microsoft sean fluidos, al no tener que cruzar bases en la subida interna.
- GOBERNANZA ZERO-TRUST: Nadie (excepto tu administrador) controla hacia dónde va la data. Con cero programación pueden deshabilitar extrusiones desde Odoo sin tocar Servidores.
- INYECCIÓN LISTA DE ODOO ORM: No hacemos cruces raw a PostgreSQL, sino que utilizamos y heredamos de tu misma librería segura search(). Por tanto los permisos básicos de filtrados transaccionales aplican automáticamente.
